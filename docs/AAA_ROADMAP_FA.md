# نقشه راه ارتقای هنری و فنی Last Fortress

آخرین به‌روزرسانی: 2026-10-19
شاخهٔ اصلی: `main`

- [x] تولید خودکار مدل‌های دشمن و باس با هندسهٔ اختصاصی و سیلوئت‌های متمایز.
- [x] اسکلت‌بندی glTF و وزن‌دهی rigid به استخوان‌ها برای مدل‌های تولیدشده.
- [x] کلیپ‌های پایهٔ Idle، Walk، Run، Attack، Hit و Death؛ کلیپ‌های ویژه مانند Roar.
- [x] جزئیات زره، سلاح، هسته‌های emissive و متریال‌های PBR پایه.
- [x] ریگ‌های ویژه‌تر برای پاهای عنکبوت و دم قطعه‌ای اژدها؛ حرکت دنبال‌شوندهٔ دم در Roar.
- [x] اعتبارسنجی دارایی‌ها در فرایند build.
- [x] اجرای موفق Web Build و Android debug APK در اجرای GitHub Actions شمارهٔ 189، commit `98776706578d94214e01ca38cdab3c269e86bf0a`.
- [ ] تست بصری و عملکردی واقعی روی دستگاه کاربر؛ build موفق به‌تنهایی تأیید کیفیت بصری یا FPS نیست.

## مرحلهٔ بعد — ادغام و QA داخل بازی
1. بررسی کنید هر مدل glTF واقعاً از manifest بارگذاری می‌شود و مدل fallback ناخواسته نمایش داده نمی‌شود.
2. با `?graphicsDebug=1`، FPS، frame time، draw calls، triangles و کیفیت رندر را در صحنهٔ شلوغ ثبت کنید.
3. حرکت Idle/Walk/Run/Attack/Hit/Death و انیمیشن‌های ویژه را برای دشمن، عنکبوت، اژدها و باس‌ها جداگانه بررسی کنید.
4. مدل‌های pooled را پس از مرگ، تغییر فاز باس و بازگشت به pool بررسی کنید؛ scale، pose، material و animation state نباید از نمونهٔ قبلی باقی بماند.
5. روی موبایل میان‌رده و دسکتاپ، افت فریم، حافظه، بارگذاری اولیه، restart و تغییر صحنه را بسنجید.

## مرحلهٔ بعد — کیفیت هنری
1. بازبینی تناسبات، silhouette و خوانایی مدل‌ها از فاصلهٔ دور و زاویهٔ دوربین واقعی بازی.
2. بهبود UV و کیفیت بافت‌های base color، normal، roughness و metallic؛ کنترل seams و جهت بافت.
3. افزودن وزن‌دهی نرم در مفاصل ضروری؛ وزن‌دهی rigid فعلی ممکن است در خم‌شدن زانو/آرنج مکانیکی دیده شود.
4. ساخت کلیپ‌های اختصاصی برای گونه‌ها؛ حرکت پای عنکبوت، دم و بال اژدها، حملهٔ باس و واکنش ضربه باید با اسکلت اختصاصی هماهنگ باشد.
5. ساخت LODهای مناسب و کاهش هزینهٔ سایه/متریال برای دشمن‌های پرتعداد.
6. جایگزینی مرحله‌ای مدل‌های procedural با مدل‌های هنری sculpt/retopo‌شده در صورت دسترسی به pipeline هنری؛ مدل‌های procedural به‌تنهایی تضمین‌کنندهٔ کیفیت AAA نیستند.

## مرحلهٔ بعد — بهینه‌سازی و تحویل
1. ثبت baseline و مقایسهٔ قبل/بعد برای FPS، frame time، draw calls، triangle count، زمان load و حافظه.
2. بررسی dispose و cache منابع مشترک، texture memory، animation mixerها و cleanup صحنه.
3. اجرای build وب و Android از یک commit واحد؛ نگهداری APK و commit SHA کنار هم.
4. تحویل APK برای آزمون کاربر، دریافت اسکرین‌شات/ویدئوی واقعی و رفع باگ‌های بازتولیدپذیر پیش از مرحلهٔ بعد.

## معیار پایان
- Build سبز فقط سلامت کامپایل و بسته‌بندی را نشان می‌دهد.
- کیفیت بصری، پایداری و عملکرد فقط پس از تست runtime روی دستگاه قابل تأیید است.
- تا پیش از تأیید بافت‌های هنری، deformation مناسب، انیمیشن‌های اختصاصی و QA واقعی، پروژه «AAA کامل» نام‌گذاری نمی‌شود.
